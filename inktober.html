--- title: Inktober permalink: /inktober/ --- {%- comment -%} The grid builds itself from _data/inktober.yml: every prompt gets a cell, and a cell goes live when a file with a matching `day:` shows up in _inktober//. So the page is complete on October 1st and fills in over the month — nothing to edit here as days get drawn. Deliberately no CSS in stylesheets/style.css. Cloudflare caches that file for four hours, so a layout tweak here would be invisible to everyone but you for most of a day. Tachyons classes plus a little inline style ship instantly. {%- endcomment -%}

I'm learning to draw. Inktober is a drawing challenge: one prompt a day for the month of October, in ink, no undo. I doodle it, photograph the page, and put it here. These live apart from the writing on purpose — thirty-one days of a beginner's ink would bury everything else on the front page, and that isn't the trade I want.

{%- comment -%} A day dated in the future is still in `site.inktober` — Jekyll keeps it in the collection but refuses to *write* its page (same `future: false` rule as posts). Left alone, the grid would render a live tile pointing at a 404. So every tile is gated on the day's date having arrived, and `inked` is counted the same way, which also keeps the count honest. `site.future` is true under `jekyll serve --future`, where the pages do get written. {%- endcomment -%} {% assign now = site.time | date: '%s' | plus: 0 %} {% assign years = site.data.inktober | sort: "year" | reverse %} {% for y in years %} {% assign days = site.inktober | where: "year", y.year %} {% assign total = y.prompts | size %} {% assign inked = 0 %} {% for d in days %} {% assign ts = d.date | date: '%s' | plus: 0 %} {% if site.future or ts <= now %}{% assign inked = inked | plus: 1 %}{% endif %} {% endfor %}
